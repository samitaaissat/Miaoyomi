# Miaoyomi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver source-based manga and prose discovery/read/offline in a single self-hosted PWA with standard CBZ/EPUB persistence.

**Architecture:** Thin downstream Uchiyomi branch; isolated LNReader service; separate EPUB/prose module reusing accounts and shell. Deploy one Docker Compose stack in an x86 LXC guest behind the user's existing reverse proxy.

**Tech Stack:** Existing Fastify/TypeScript, Postgres, Next.js/React, IndexedDB; Node 24 and QuickJS for novel plugins; EPUB 3.3, CBZ, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-05-miaoyomi-design.md`

## Global Constraints

- All durable server reading content is CBZ (manga) or EPUB (novels); no raw chapter HTML database/disk cache.
- Keep Fastify, application authentication and user ownership. The user initially read Fastify as Fastly and explicitly corrected this.
- Target Linux amd64 in LXC on the user's three-node Proxmox cluster behind their existing reverse proxy; no new reverse-proxy service or invented cluster replication.
- Preserve the existing image/manga model. Add prose modules in separate files.
- Use actual LNReader published plugins, not replacement custom scrapers or URL-import-only UX.
- HTTP source blocks and unsupported plugin capabilities are explicit failures, never successful empty results.
- Meaningful tests precede implementation. Keep remote-source live tests opt-in, deterministic fixtures in ordinary tests.
- Do not publish, push, or create a remote GitHub fork. Work on local branch `codex/miaoyomi-novels`.
- The interface contract below is binding across independent tasks. Coordinate any required deviation before implementation.

## Shared interface contract

### Novel engine (internal HTTP)

`Authorization: Bearer ${NOVEL_ENGINE_TOKEN}` on every endpoint except `GET /healthz`.

- `GET /healthz` → `{ok:true}`.
- `GET /v1/sources` → `{sources: EngineSource[]}`.
- `POST /v1/sources/:id` with `{enabled:boolean}` → `{source:EngineSource}`; enabled sources only can invoke.
- `GET /v1/sources/:id` → `{source:EngineSource}` including runtime filter definitions.
- `POST /v1/invoke` with `{sourceId, method, args}` → `{result:unknown}`. Methods are exactly `popularNovels`, `searchNovels`, `parseNovel`, `parsePage`, `parseChapter` and `resolveUrl`.
- `POST /v1/asset` with `{sourceId,url}` → binary public image data with a validated image Content-Type; uses the same source network guard.

`EngineSource = {id,name,lang,site,version,enabled,supported,reason?:string,filters?:Record<string,unknown>,supportsLatest:boolean}`. `supported` means host capability support, not a promise the remote site is available. HTTP errors use `{error:string,message:string}` and status 400 for invalid calls, 404 unknown source, 409 disabled/unsupported source, 502 source failures/challenges, 504 deadline, 401 missing token. The runtime may add an `error` code to a source for display but does not drop failing sources silently.

### Public novel API (existing account authentication)

`NovelCard = {sourceId:string,path:string,title:string,cover?:string,id?:string}`.

`NovelChapter = {id:string,path:string,title:string,number?:number,position:number,saved:boolean}`.

`NovelDetail = {id,sourceId,path,title,cover?,author?,summary?,language,chapters:NovelChapter[],totalPages?:number,inLibrary:boolean}`.

`NovelPayload = {novelId,chapterId,novelTitle,chapterTitle,html,sourceUrl,archiveRevision,previousChapterId?:string,nextChapterId?:string}`. `html` is sanitized and self-contained for reading, with embedded images represented as data URLs derived from the EPUB. EPUB XHTML uses local standard asset links, not data URLs.

`NovelProgress = {chapterId:string,position:number,completed:boolean,updatedAt:number,mutationId:string}`. `position` is a fraction 0..1; `updatedAt` is client Unix milliseconds, validated/clamped on the server. Completed status per chapter is monotonic; an old outbox update cannot overwrite newer position/progress. The outbox is account-scoped.

- `GET /api/novels/sources` → `{sources:EngineSource[]}`.
- `POST /api/novels/sources/:id` with `{enabled}` → `{source}`; admin only.
- `GET /api/novels/browse?sourceId&mode=popular|latest&page=1&filters=<JSON>` → `{items:NovelCard[],page,hasMore}`.
- `GET /api/novels/search?sourceId&q&page=1` → same shape.
- `GET /api/novels/detail?sourceId&path` → `NovelDetail`, upserting metadata but not downloading the whole book.
- `GET /api/novels/:id` → saved `NovelDetail`.
- `POST /api/novels/:id/chapters/refresh` with `{page:string}` → `NovelDetail` merging source pagination.
- `POST /api/novels/:id/chapters/:chapterId/open` → `NovelPayload`; retrieves absent content and atomically saves to EPUB before serving it.
- `GET /api/novels/:id/chapters/:chapterId` → saved `NovelPayload`, 404 if absent.
- `GET /api/novels/library` → `{items:(NovelDetail & {progress?:NovelProgress})[]}` for this user's saved/reading books.
- `PUT /api/novels/:id/library` with `{saved:boolean}` → `{ok:true}`.
- `GET /api/novels/:id/progress` → `{progress:NovelProgress|null}`.
- `PUT /api/novels/:id/progress` with `NovelProgress` → `{progress:NovelProgress}`.
- `GET /api/novels/:id/export.epub` → standard saved-chapter EPUB; 404 before any chapter is saved.

Static Next export routes use query strings: `/novels`, `/novels/title?sourceId=...&path=...` or `?id=...`, `/novels/read?novelId=...&chapterId=...`. Do not create runtime dynamic `[id]` routes that cannot be statically exported.

## Task 2: Standard EPUB storage module

**Owner/files:** `bff/src/lib/novels/archive.ts`, `sanitize.ts`, `identity.ts`, `types.ts` and focused test files `bff/test/novelArchive.test.ts`, `novelIdentity.test.ts`. This task owns BFF package dependency changes if needed. Root owns other novel module files.

**Consumes:** transient source HTML, novel/chapter metadata and an injected allowed-image fetch callback.
**Produces:** exported contracts below. No database calls; root holds the authoritative Postgres lock around archive mutation.

```ts
type ArchiveNovel = { id:string; title:string; language:string; author?:string; sourceUrl:string; sourceId:string; sourcePath:string };
type ArchiveChapter = { id:string; title:string; position:number; sourcePath:string; sourceUrl:string; html:string };
type AssetFetcher = (url:string) => Promise<{bytes:Buffer;contentType:string}>;
async function appendChapter(root:string, novel:ArchiveNovel, chapter:ArchiveChapter, fetchAsset:AssetFetcher): Promise<{revision:string}>;
async function readChapter(root:string, novelId:string, chapterId:string): Promise<{html:string;revision:string;chapterIds:string[]}|null>;
async function inspectArchive(root:string, novelId:string): Promise<{revision:string;chapters:Array<{id:string;title:string;position:number;sourcePath:string;sourceUrl:string}>}|null>;
function archivePath(root:string, novelId:string): string;
function novelId(sourceId:string, path:string): string;
function chapterId(novelId:string, path:string): string;
```

- [ ] Write and run failing tests for a first chapter, out-of-order appends, re-opening with a new module instance, escaping malicious HTML, preserving supported inline images, invalid identity/path traversal and a failed append retaining the prior EPUB.
- [ ] Implement deterministic path-based SHA-256 IDs; keep source strings exact apart from safe canonical rules, never names or ordinal numbers.
- [ ] Implement sanitized well-formed XHTML and embedded allowed image assets, with fetch failures surfaced rather than silently claiming a complete offline chapter. Refuse active SVG/scripts/forms/external CSS; preserve prose semantic structure.
- [ ] Implement EPUB 3.3: uncompressed first mimetype, container, OPF required metadata/spine/manifest, nav and chapter XHTML. Store chapter provenance in valid namespaced metadata for reconciliation. Read all content back from EPUB; no chapter HTML sidecar or database body.
- [ ] Atomically replace via same-directory temp file, fsync and rename; clean failed temp files. Serialize calls in-process as a second guard, but document caller's database lock for multiple processes.
- [ ] Verify independent ZIP/XML parsing and EPUBCheck against a generated multi-chapter/image fixture. `readChapter` returns self-contained sanitized HTML using EPUB asset bytes as data URLs.
- [ ] Run focused tests and BFF build; report exact commands/results and example EPUB for root verification.
