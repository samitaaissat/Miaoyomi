# Native Proxmox installation

The Proxmox node runs an interactive Bash wizard that creates an unprivileged x86_64 Alpine 3.24 LXC for Miaoyomi. By default, it also invokes the official community FlareSolverr wizard to create a separate native Debian LXC. No Docker, Podman or other container runtime runs inside either LXC. This requirement does not prohibit the Proxmox nesting feature: the app exposes `--nesting yes|no` with `no` as its default; the solver retains the official installer's feature settings.

The app wizard asks for CT ID, hostname, resource limits, root/template storage, bridge, DHCP or static IPv4, optional VLAN, HTTPS public origin, app port, an optional read-only existing manga bind mount and solver choice. App defaults remain 4 cores, 6144 MiB RAM and 32 GiB disk, independent of the solver. It shows a summary, rejects an occupied app ID and preserves a failed new app guest for diagnosis. The official solver wizard owns its resource/network questions and failure handling.

`--flaresolverr yes` is the default and starts that separate wizard. `--flaresolverr no` disables the integration. `--flaresolverr-ctid ID` reuses an existing local LXC with the native community solver service; `--flaresolverr-url URL` uses an existing endpoint. `--yes` cannot automate the official new-solver wizard and must be paired with an existing ID/URL or solver disabled. A dry run makes no changes. The wrapper identifies the actual newly created solver instead of assuming its preferred CT ID was retained, verifies native service identity, discovers its address and health-checks it from the app guest before configuring clients. It must refuse ambiguous discovery instead of selecting an unrelated existing guest.

Installation sources are an HTTPS Git repository/ref or a local source directory already copied to the Proxmox node. The configured remote is `https://github.com/samitaaissat/Miaoyomi.git`; the remote installation command only becomes available after these changes are published at the selected ref. Never substitute the original Uchiyomi repository. Local transfer excludes credentials, libraries, caches, dependency directories and VCS metadata. The host passes validated configuration and a source bundle to the app guest; the guest installer reads no interactive input.

Alpine runs PostgreSQL 18, Suwayomi 2.3.2243 (verified standalone JAR), the Node 24 novel engine and the Node 24 Fastify app serving `web/out`. OpenRC supervises application processes under distinct unprivileged users. Database and source engines bind loopback; the app listens on its selected LAN port behind the existing HTTPS reverse proxy. A separate novel user cannot read application/database secrets or libraries. FlareSolverr and Chrome run natively under systemd in the official Debian guest. The app and Suwayomi connect to its private port 8191. No Alpine FlareSolverr installation is attempted. Suwayomi remains headless with KCEF disabled; the solver does not provide novel-plugin browser access.

Persistent app settings live under `/etc/miaoyomi` and books/state under `/var/lib/miaoyomi`. Versioned application releases live under `/opt/miaoyomi/releases`, with `/opt/miaoyomi/current` selecting the active release. Override every environment path with a container-era absolute default. Never recursively chown the existing collection. Generate secrets once with restrictive ownership. Save the solver URL and optional local CT ID as connection metadata. Use a static address or DHCP reservation; a saved CT ID is not a continuous network discovery service. Operators supply private routing and firewall access from the app to the solver; the installer does not publish the solver through the proxy or change firewall policy.

The installed `miaoyomi` command provides status, logs, restart, update, explicit Suwayomi update, backup and `set-solver --url URL [--ctid ID]`. An empty URL disables the integration. Changing a connection validates/reaches the new endpoint before mutation, backs up before replacing managed settings, updates app and Suwayomi together and preserves unrelated configuration and secrets. Host `--reconnect APP_CTID --flaresolverr-ctid SOLVER_CTID` rediscovers the solver's current address and delegates to this command; an explicit URL is supported for a remote endpoint. Host `--update-solver APP_CTID --flaresolverr-ctid SOLVER_CTID` first runs the local solver's official `/usr/bin/update`, then reconnects. Both ID-based operations require the guests on the invoking node.

App updates use the saved Git source/ref or an explicitly supplied replacement local tree. Build before downtime. Stop writers and back up PostgreSQL, app configuration, source-engine state and generated books before cutover. Preserve the previous release and backup on failure; never automatically roll code back across a database migration. An app-only update does not upgrade Alpine/PostgreSQL majors, refresh the source registry or update Suwayomi/FlareSolverr. App archives include solver connection metadata but no solver guest files or service state. Keep complete CT backups of both guests and separate backups of host bind mounts; official solver updates follow upstream's own lifecycle.

Validation includes Bash syntax, ShellCheck, command-flow tests with mocked Proxmox tools, source packing/validation tests, native management failure-path tests and cross-component connection checks. Creation, Alpine/Debian boot, real OpenRC/systemd supervision, official wizard behavior, challenge handling, reconnect after address changes and restoration of both CTs remain real-Proxmox acceptance checks. These results cannot be claimed from this macOS workspace.
